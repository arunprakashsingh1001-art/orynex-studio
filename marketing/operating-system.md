# Orynex Studio — Marketing Operating System

## Operating goals

1. Publish consistent, high-quality organic content.
2. Demonstrate real capability across design, engineering, architecture, and optimization.
3. Convert relevant interest into valid project enquiries.
4. Build a reliable baseline before spending on advertising.

No growth, ranking, or lead-volume result is guaranteed.

## Roles (one person can fill multiple roles)

| Role | Responsibility | Done means |
|---|---|---|
| Strategist | Select audience/problem/service | One clear goal and audience per asset |
| Producer | Script, visuals, edit, captions | Draft is complete and files are named |
| Brand/QA reviewer | Check accuracy, design, rights, CTA | Checklist passed or issues recorded |
| Publisher | Upload, schedule, accessibility | Correct platform, title, caption, cover |
| Analyst | Record performance after 7 days | Metrics and one learning are logged |

## Weekly cadence (zero-budget)

- Monday: select one audience problem and one primary service; review last week's results.
- Tuesday: script one 15–25 second vertical video and one carousel/post.
- Wednesday: produce/edit; prepare captions, title, cover, alt text, and CTA.
- Thursday: factual, rights, mobile readability, and link QA; approve or revise.
- Friday: publish approved asset; adapt the same core idea for the other platform.
- Saturday: reply to genuine comments and enquiries; no unsolicited mass messaging.
- Sunday: record metrics, learnings, and next week's experiment.

Adjust days to your real availability; consistency matters more than volume.

## Production workflow

1. **Brief:** audience, problem, service, single objective, proof available, CTA.
2. **Draft:** hook, useful middle, one CTA, caption, platform title.
3. **Asset creation:** 9:16 master (1080×1920 target), safe margins, captions burned in or platform captions.
4. **QA:** use the checklist below; label demo visuals as concepts.
5. **Approval:** asset owner confirms copy, footage rights, and factual claims.
6. **Publish:** upload natively or via a scheduler you have explicitly authorized.
7. **Log:** public URL, publish date, asset ID, baseline metrics.
8. **Review:** after 7 days, compare retention, shares/saves, profile visits, link clicks, qualified enquiries.
9. **Improve:** change one variable at a time (hook, opening visual, length, or CTA).

## Pre-publish checklist

- [ ] First 1–2 seconds communicate a relevant idea.
- [ ] One primary audience and one objective.
- [ ] Copy is clear, grammatical, and brand-consistent.
- [ ] Brand line is exact where used: “Your Idea Deserves a Better Digital Experience.”
- [ ] Supporting line is exact where used: “Design. Engineering. Performance.”
- [ ] CTA is specific and links to the correct destination.
- [ ] Text is readable on a small screen and not hidden by app UI.
- [ ] Captions/subtitles checked against voice-over.
- [ ] Audio, fonts, footage, and images are licensed/authorized.
- [ ] No unverified statistics, client claims, testimonials, logos, or guarantees.
- [ ] Demo work is labelled as concept/demo when applicable.
- [ ] No private data, API keys, or client secrets visible in screen recordings.
- [ ] Spelling, crop, sound, export, cover, caption, title, and link checked.
- [ ] Approval recorded before posting.

## Response SLA and enquiry handoff

- Check comments and enquiries on a sustainable schedule (e.g., once per day).
- Reply helpfully; do not promise delivery times, prices, or outcomes before validating scope.
- For enquiries, collect only necessary details: name/company (optional), contact method, service, goal, target date, budget range (optional), and relevant links.
- Move sensitive details to a suitable private channel; never request passwords or payment credentials.
- Mark each lead: New → Needs clarification → Qualified → Proposal → Won/Lost.
- Follow up only where permission and applicable rules allow.

## Naming convention

Use: `YYYY-MM-DD_platform_service_concept_v01`

Examples:
- `2026-11-02_reels_webdesign_before-after_v01`
- `2026-11-04_shorts_engineering_explainer_v01`
